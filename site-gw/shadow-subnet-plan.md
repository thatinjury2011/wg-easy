## 1. 问题是什么

需求：WG 把各站点的**局域网整体转发**进 VPN（NPM 反代、手机直连设备），而不只是"SSH 到网关"。

障碍：多个站点的 LAN 网段目前可能**相同**（例如都是 `192.168.1.0/24`，甚至同一台设备都是 `192.168.1.208`）。

三层路由靠目的地址唯一决定路径，所以：

```
VPS 路由表里只能有一条 192.168.1.0/24 → 只能属于一个站点
```

一旦有两个站点重名 → 另一个站点永远不可达，且**无法靠配置技巧绕过**。

---

## 2. 三个候选方案

| 方案 | 站点内部要改吗 | 跨站访问用什么地址 | 评价 |
|---|---|---|---|
| **A. 改网段** | ✅ 改主路由 LAN IP + DHCP + 静态设备 | 真实地址（`192.168.10.208`） | 治本、心智负担最低；现场改造工作量大 |
| **B. 影子段（1:1 NAT / NETMAP）** | ❌ 完全不动 | 别名（`10.99.10.208`） | 不动现场，但要维护对照表；IPv4 only |
| **C. DNAT 端口映射** | ❌ 不动 | `wg-easy:18080` 之类 | 最省事，但只是"端口映射"，不是真的 LAN 转发 |

**当前倾向**：B（影子段）—— 既能实现"LAN 转发"，又不用动现场设备。
若新站点从一开始就能定唯一网段，也可以新站用 A、老站用 B（但文档要写清，别混）。

## 3. 影子段设计草案

### 3.1 地址规划

| 站点 | 真实 LAN | 影子段（唯一） | 网关隧道地址 |
|---|---|---|---|
| A | `192.168.1.0/24` | `10.99.10.0/24` | `10.8.0.10` |
| B | `192.168.1.0/24` | `10.99.20.0/24` | `10.8.0.20` |
| C | `192.168.1.0/24` | `10.99.30.0/24` | `10.8.0.30` |

规则：`10.99.<站点号>.0/24` ↔ 该站点 `192.168.1.0/24`，**最后一段一一对应**（`.208 → .208`）。

必须避开：`10.8.0.0/24`（VPN 客户端）、`10.42.42.0/24`（wg-easy 容器）、`172.16.0.0/12`（Docker）、`172.28.0.0/24`（proxy-net）。

### 3.2 站点网关（wg-quick）

```ini
PostUp   = sysctl -w net.ipv4.ip_forward=1
PostUp   = iptables -A FORWARD -i %i -j ACCEPT; iptables -A FORWARD -o %i -j ACCEPT
# 出：真实源 → 影子源
PostUp   = iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o %i -j NETMAP --to 10.99.10.0/24
# 入：影子目的 → 真实目的
PostUp   = iptables -t nat -A PREROUTING -d 10.99.10.0/24 -i %i -j NETMAP --to 192.168.1.0/24
PostUp   = iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu
# PostDown 写对应 -D
```

`AllowedIPs`（客户端侧）需包含：

```
10.42.42.0/24      # 服务端
10.8.0.0/24        # 其它 VPN 客户端
172.16.0.0/12      # 回程：让站点设备能回包给 Docker 网段的源地址
10.99.20.0/24 ...  # 其它站点的影子段（不是真实 LAN）
```

### 3.3 wg-easy 面板字段

| 字段 | 站点 A |
|---|---|
| 允许的IP（下发） | `10.42.42.0/24, 10.8.0.0/24, 172.16.0.0/12, 10.99.20.0/24, 10.99.30.0/24` |
| **服务端允许的IP** | `10.8.0.10/32, 10.99.10.0/24` ← 填影子段，**不能填 `192.168.1.0/24`** |
| 客户端钩子脚本 | 留空（规则交给脚本的 `--alias`） |

服务端会生成 3 条互不冲突的路由：`10.99.10.0/24 dev wg0` 等。

### 3.4 NPM / 主路由

- NPM 的 Forward Hostname 填**影子地址**：`10.99.10.208`（不冲突）
- 站点内设备要访问别站 → 主路由加 `10.99.20.0/24 → 网关A LAN IP`（可选，只在本站设备需要跨站时加）

### 3.5 已知限制

- **仅 IPv4**（NETMAP 只做 IPv4）
- 设备日志里看到的对端地址是影子地址
- 带 IP 载荷的协议可能异常（FTP 主动模式、SIP、IPsec）
- 需要 `xt_NETMAP`（Debian/Armbian 自带；OpenWrt 需 `iptables-mod-nat-extra`）

## 4. 明天需要确认的 5 件事

1. **走哪个方案**：A 改网段 / B 影子段 / C 端口映射（或"新站 A + 老站 B"）
2. **影子段编号规则**：是否采用 `10.99.<站点号>.0/24`（站点号 = 隧道地址第 4 段 / 10）
3. **是否给 `install.sh` 加 `--alias=<CIDR>`**（自动探测真实 LAN、生成 NETMAP、`AllowedIPs` 自动带 `172.16.0.0/12`）
4. **是否需要"本站设备访问别站"**（决定要不要在主路由加影子段路由）
5. **nps 是否继续并行**（当前结论：nps 管公网业务、WG 管管理通道；若影子段落地，公网业务也可以改走 WG+NPM）

## 5. 附带记录：这几天确定下来的其他结论

| 主题 | 结论 |
|---|---|
| wg-easy 部署 | 容器 bridge 模式下 wg0 只在容器 netns 内，**NPM 看不到 VPN 内网**；要让 NPM 直接反代内网，需 `network_mode: host`（另有 DOCKER-USER 放行 + 源地址 SNAT 两个配套问题） |
| 回程 SNAT | 若不想改客户端 `AllowedIPs`，可在服务端加 `iptables -t nat -I POSTROUTING 1 -o wg0 -s 172.16.0.0/12 -j MASQUERADE` |
| UI 能否配规则 | 客户端页有「钩子脚本」，但**仅 wg-quick 客户端有效**，导入官方 App 会报错；与脚本注入二选一 |
| 客户端地址 | 保持面板默认 `10.8.0.x`，不要改成和 `10.42.42.0/24` 同段 |
| DNS | 面板全局 DNS 建议留空，避免影响客户端解析 |
| 主路由 | 每个站点仍需 1 次静态路由或 DHCP option 121（脚本管不到） |
