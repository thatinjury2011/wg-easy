# 影子段方案（已确认并实现）

> 状态：**已确认并已实现**（2026-11-15）
> 对应实现：`install.sh --alias=<CIDR>` ｜ 使用说明见 [`README.md`](./README.md) 第 11 章

---

## 1. 要解决的问题

需求：让 WG 把各站点的**整个局域网**转发进 VPN（NPM 反代、手机直连设备、站点互访），而不只是"SSH 到网关"。

障碍：多个站点的 LAN 网段可能**完全相同**（例如都是 `192.168.1.0/24`，同一设备都是 `192.168.1.208`）。

三层路由靠目的地址唯一决定路径，VPS 路由表里只能存在一条 `192.168.1.0/24`：

```
VPS 路由表：192.168.1.0/24 dev wg0   ← 只能属于一个站点，另一个永远不可达
```

**无法靠配置技巧绕过，只能让"跨站可见的地址"唯一。**

---

## 2. 方案：影子段（1:1 地址翻译 / NETMAP）

给每个站点发一个**全局唯一别名网段**，网关在包进出隧道时做 1:1 地址改写：

```
             真实地址（站内用）              别名地址（跨站用）
站点 A:  192.168.1.208  ←──NETMAP──→  10.10.1.208
站点 B:  192.168.1.208  ←──NETMAP──→  10.10.2.208
站点 C:  192.168.1.208  ←──NETMAP──→  10.10.3.208
```

- 别名不是虚拟 IP，不需要在设备上配置
- 内核 conntrack 记住映射，回程自动改回
- 站内设备**一个字节都不用改**

### 候选方案对比

| 方案 | 站点内部要改吗 | 跨站访问地址 | 结论 |
|---|---|---|---|
| A 改网段（站点 LAN 唯一化） | ✅ 改主路由 + DHCP + 静态设备 | 真实地址 | 治本，有能力时优先 |
| **B 影子段（本方案）** | ❌ 不动 | 别名 `10.10.X.Y` | 现场改不动时的解法 |
| C 端口映射（DNAT） | ❌ 不动 | `wg-easy:18080` | 只是端口映射，不是 LAN 转发 |

## 3. 地址规划（已确认）

### 3.1 编号规则

> **别名段第 3 段 = 站点编号，与真实 LAN 无关；第 4 段（主机位）一一对应。**

| 站点 | 真实 LAN | 别名（影子段） | 小主机 LAN IP | 隧道地址 |
|---|---|---|---|---|
| A | `192.168.1.0/24` | `10.10.1.0/24` | `192.168.1.10` | `10.8.0.10` |
| B | `192.168.1.0/24` | `10.10.2.0/24` | `192.168.1.10` | `10.8.0.20` |
| C | `192.168.1.0/24` | `10.10.3.0/24` | `192.168.1.10` | `10.8.0.30` |

记忆法：`10.10.2.208` = "站点 B 的 `192.168.1.208`"。

### 3.2 约束

| 约束 | 原因 |
|---|---|
| 别名**掩码**必须与真实 LAN 相同 | NETMAP 只替换前缀、保留主机位 |
| 主机位保留（`.208 → .208`） | 便于对照、避免配错 |
| 别名不得与真实 LAN 重叠 | 直连路由冲突 |
| 别名不得与 `10.8.0.0/24`、`10.42.42.0/24`、`172.16.0.0/12`、`172.28.0.0/24` 重叠 | 与 VPN/Docker 冲突 |
| 站点真实 LAN 不能是 `10.10.x.x` | 与别名父网段冲突 |
| 统一放 `10.10.0.0/16`（避开 `.0.0/24` 与 `.10.0/24`） | 便于管理与排障 |

容量：`10.10.0.0/16` 可切出 254 个 `/24`。

## 4. 网关侧规则（脚本自动注入）

站点 A（真实 `192.168.1.0/24`，别名 `10.10.1.0/24`，LAN 网卡 `eth0`）：

```ini
# site-gw:rules  由安装脚本生成，请勿手工编辑
PostUp   = iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o %i -j NETMAP --to 10.10.1.0/24
PostUp   = iptables -t nat -A PREROUTING -d 10.10.1.0/24 -i %i -j NETMAP --to 192.168.1.0/24
PostUp   = iptables -t nat -A POSTROUTING -o eth0 ! -s 192.168.1.0/24 -j MASQUERADE
PostUp   = iptables -A FORWARD -i %i -j ACCEPT; iptables -A FORWARD -o %i -j ACCEPT
PostUp   = iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu
# PostDown 各条 -D，顺序反向
```

三条核心规则的作用：

| 规则 | 方向 | 作用 |
|---|---|---|
| `POSTROUTING -s LAN -o %i -j NETMAP --to ALIAS` | 出隧道 | 真实源 → 别名源，服务端才认得出这是谁 |
| `PREROUTING -d ALIAS -i %i -j NETMAP --to LAN` | 入隧道 | 别名目的 → 真实目的 |
| `POSTROUTING -o <LAN 网卡> ! -s LAN -j MASQUERADE` | 投递给设备 | 把"非本站 LAN"的源统一改成本站网关 IP，让设备回包直连网关、不经过主路由 |

> 普通模式下注入的 `-s LAN -o %i -j MASQUERADE` 在影子模式下**必须移除**（与 NETMAP 争抢匹配），脚本会自动清理带 `# site-gw:` 标记的旧规则，因此两种模式可来回切换、不会叠加。

### 客户端 AllowedIPs

```ini
AllowedIPs = 10.42.42.0/24, 10.8.0.0/24, 172.16.0.0/12, 10.10.2.0/24, 10.10.3.0/24
```

- `10.10.2/3.0/24`：对端站点**别名**（不写对端真实 LAN）
- **`172.16.0.0/12` 必须有**：NPM 容器发出的包会被 Docker SNAT 成 `172.17.0.1`，设备回包经网关还原后目的地址就是它；缺了这条回包会被丢到公网默认路由（现象：请求发得出、一个字节收不到）
- 脚本会自动补上 `172.16.0.0/12`

## 5. 主路由改什么

**关键结论：纯"外 → 内"访问时，主路由一条路由都不需要加。**

原因：网关把源地址改成本站网关自己的 LAN IP（同网段），设备回包是二层直连，压根不查询主路由的路由表。

```
NPM/手机 → 10.10.1.208 → 网关（NETMAP → 192.168.1.208，源改成 192.168.1.10）
       → 设备收到"源=192.168.1.10 的请求" → 回包直连 192.168.1.10
       → 网关 conntrack 还原 → 隧道 → 回 VPS/NPM
```

### 只有"站内设备主动访问别站"才需要加

| 目的网段 | 下一跳 | 场景 |
|---|---|---|
| `10.10.<别站号>.0/24` | 本站网关 LAN IP | 本站设备访问别站设备 |

站点 A 的主路由（`192.168.1.1`）：

```
10.10.2.0/24 → 192.168.1.10
10.10.3.0/24 → 192.168.1.10
```

**不需要**再加 `10.8.0.0/24`、`10.42.42.0/24`、`172.16.0.0/12`（这些源都已被网关改写）。

### 加在哪

| 路由器 | 位置 |
|---|---|
| OpenWrt / iStoreOS | 网络 → 路由 → 静态路由（接口选 `lan`） |
| 小米 / 红米 | 部分型号无此功能，改用 DHCP option 121 |
| 爱快 iKuai | 网络设置 → 静态路由 |
| RouterOS | `/ip route add dst-address=10.10.2.0/24 gateway=192.168.1.10` |
| 华硕 ASUSWRT | 高级设置 → 路由 → 静态路由列表 |

### 主路由没有静态路由功能时：DHCP option 121

```
121,10.10.2.0/24,192.168.1.10,10.10.3.0/24,192.168.1.10
```

设备拿到租约即自动装路由（Windows/macOS/iOS/Android/Linux/OpenWrt 均支持；个别老 IoT 不认）。

### 前提条件（"主路由零改动"成立的基础）

1. 设备与网关**同一二层网段**（中间没有第三台路由/NAT）
2. 网关能 ARP 到设备（无 AP 隔离 / 客户端隔离）
3. 设备没有"只允许特定源 IP"的白名单（模式 N 下源是网关 IP）
4. 协议不依赖客户端真实 IP（FTP 主动模式 / SIP / IPsec 例外）

## 6. wg-easy 面板与 NPM

| 位置 | 站点 A 填什么 |
|---|---|
| 面板 → **服务端允许的IP** | `10.8.0.10/32, 10.10.1.0/24`（**别名，不是真实 LAN**） |
| 面板 → 允许的IP | `10.42.42.0/24, 10.8.0.0/24, 172.16.0.0/12, <对端别名>` |
| 面板 → 客户端钩子脚本 | **留空**（规则由 `--alias` 注入，避免叠加） |
| NPM → Forward Hostname | `10.10.1.208` |

> NPM 是容器，`10.10.x.x` 的路由在宿主机上（或 wg-easy 容器里）。NPM 能访问 VPN 内网仍依赖"wg-easy 改 host 网络"或"DNAT 方案"——影子段不改变这个前置条件。

## 7. 相对普通模式新增的步骤

| # | 变更 | 位置 |
|---|---|---|
| 1 | 删除 `POSTROUTING -s LAN -o wg0 -j MASQUERADE` | 网关（脚本自动） |

| 3 | 新增 `PREROUTING -d ALIAS -i wg0 -j NETMAP --to LAN` | 网关（脚本自动） |

## 8. 验证

```bash
# 模块与规则
lsmod | grep netmap || modprobe xt_NETMAP
iptables -t nat -S | grep -E 'NETMAP|snat'
#   应看到 nm-out / nm-in 各一条 + 一条 `-o <LAN网卡> ! -s <LAN> -j MASQUERADE`
#   且【不应】看到 `-s <LAN> -o wg0 -j MASQUERADE`

# 服务端路由
docker exec wg-easy ip route | grep 10.10

# 地址翻译
conntrack -L | grep 10.10.1

# 设备侧看到的源地址（应为网关 LAN IP）
tcpdump -ni br-lan host 192.168.1.208 -c 5

# 端到端
ping 10.10.1.208
curl -sI http://10.10.1.208:5000
```

| 现象 | 原因 |
|---|---|
| 规则里有两条冲突的 MASQUERADE | 旧规则没清（重跑脚本会自动清理） |
| `NETMAP` 报错 | 内核缺 `xt_NETMAP`（OpenWrt: `iptables-mod-nat-extra`） |
| 请求发出但无回包 | `AllowedIPs` 缺 `172.16.0.0/12`，或 `-o <LAN网卡>` 的网卡名不对 |
| 站内设备 ping 不通别名 | 网关缺 `PREROUTING` NETMAP，或用户侧没加 `10.10.x/24` 到 AllowedIPs |
| 设备能通但跨站不通 | 主路由缺对端别名段路由（互访场景） |

## 9. 限制

- **仅 IPv4**（NETMAP 不支持 IPv6；IPv6 需 NPTv6，一般不启用）
- **载荷内含 IP 的协议可能异常**：FTP 主动模式、SIP、IPsec、部分联机游戏
- **源 IP 可见性**：站内设备看到的对端是"网关 LAN IP"（好处是零主路由改动；需要真源 IP 时改用普通模式 + 主路由路由）
- **需维护对照表**：`10.10.2.35` 是哪台设备只有台账知道
- **两种方案不要混用**：同一体系内统一"改网段"或"影子段"，否则地址规划会失控
